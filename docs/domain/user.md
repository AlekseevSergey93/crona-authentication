# User domain model

## Purpose

`User` represents a local account that can authenticate with an email and password. The domain model stores only a password hash; raw passwords must never enter the entity or persistence layer.

## Identity

| Field | Type | Rules |
|---|---|---|
| `id` | `UUID` | generated by the application and immutable |
| `email` | `String` | normalized, non-blank, maximum 320 characters |
| `passwordHash` | `String` | Argon2id output, non-blank, never exposed by API DTOs |
| `createdAt` | `Instant` | set once at persistence time, UTC |
| `updatedAt` | `Instant` | updated on entity modification, UTC |

The database table is `users`. The database-level unique index `users_email_uq` is the final authority for email uniqueness and protects against concurrent registration attempts.

## Email normalization

Before a user is created:

1. Reject null or blank input.
2. Trim leading and trailing whitespace.
3. Convert to lowercase with `Locale.ROOT`.
4. Reject values longer than 320 characters.

The normalized value must match the service email syntax policy: it must contain a non-whitespace local part, an `@`, and a non-whitespace domain containing a dot. This policy is intentionally provider-neutral.

Do not apply provider-specific canonicalization, such as removing dots or plus-addressing suffixes. Repository queries must receive an already normalized email.

## Password policy

The application validates raw passwords before hashing:

- minimum 12 Unicode code points;
- maximum 128 Unicode code points;
- no trimming or normalization;
- whitespace is allowed when it is part of the password;
- raw password values must never be logged or persisted.

The limits are configurable through `PASSWORD_MIN_LENGTH` and `PASSWORD_MAX_LENGTH`.

## Invariants

- A user always has an application-generated UUID.
- A user always has a normalized email.
- A user always has a non-empty password hash.
- `createdAt` is immutable after insertion.
- `updatedAt` is never earlier than `createdAt`.
- Email and password hash are not mutable through the current domain API.

## Persistence API

`UserRepository` provides:

- `findByEmail(normalizedEmail)` for login lookup;
- `existsByEmail(normalizedEmail)` for pre-checks;
- `saveNew(user)` for inserts with an immediate flush.

`saveNew` translates a PostgreSQL/Hibernate violation of `users_email_uq` to `DuplicateUserException`, which is rendered as `409 USER_ALREADY_EXISTS`. Other integrity errors remain dependency/application errors and must not be mislabeled as duplicate emails.

## Security boundary

The entity getter for `passwordHash` is for password verification inside the authentication service only. It must not be used in response DTOs, logs, error messages, or audit events. Raw password validation and Argon2id hashing belong to the application service layer.
